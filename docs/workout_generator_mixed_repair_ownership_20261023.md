## Proven protected-source root causes

`protected_source_root_cause_20261023/diagnose.py` reconstructs the first paid request's state and repair schema from the exact saved prefix, checks both real submissions, and revalidates the cached review against its original recorded context. Its assertions pass with zero provider calls. Every runtime hash matches `lookup_resume_e2e_20261023/source_hashes.json`; all retained inputs remain unchanged. `diagnosis.json` contains the evidence.

The shared design defect is split repair authority: the state projection, schema delivery and cached intent admission disagree about the available actions.

- **State contradicts schema.** `planner_context._focus_repair` advertises all six redistribution sources in `editableExerciseReferences`. `planning_tools.coordinated_repair_tool` excludes exactly those six from selectable/replacement references. Both real submissions included all six as replacement objects. The model receives contradictory action domains; this is not missing access to the fetched exercise metadata.
- **The schema is not provider-enforced.** The actual composite repair schema fails `api_client._strict_parameters_compatible`: it uses unsupported `const`, `oneOf`, cardinality and uniqueness keywords. `_strict_application_tools` returns `None`, and `_chat_call_once` sends ordinary tools instead. It also requires the entire advertised tool set to be compatible, so repairing only one schema is insufficient if another tool still disables strict delivery. Local validation correctly rejects forbidden choices, but exclusion from a non-strict schema cannot guarantee the provider will not emit them.
- **Saved intent bypasses the new source-association fix.** `_focus_repair` reuses the rejected receipt's assessment through `validate_assessment` without context. The saved assessment passes that check. The same assessment, with its original review context and request-only `_reviewRef` annotations removed, fails the existing finding/objective association check. The Clean objective is associated with finding 0; the Nordic objective has no association with finding 3's Clean Pull/Pull-Up superset concern. Thus the fresh-assessment fix is present in code but was not applied to the cached assessment used for this paid continuation. Three unnecessary protected sources survive.

The prior controlled compiler replay intentionally removed that Nordic objective and supplied a manually valid menu. It established compiler/admission behavior; it did not prove the cached-intent admission path or the model's actual constrained interface. Treating that as completion of the live repair boundary was too strong.

The complete correction must derive state and wire choices from the same code-owned action domain, require supported strict delivery for that repair surface instead of silent fallback, and apply the same source/objective association validation to fresh and reused assessment paths. Existing local conservation and coverage validation must remain. Verification must cover actual provider arguments and cached assessment admission, then one authorized live continuation. More prompt prose, another repair retry, a new contract version or relaxing the workout requirements would leave these owners inconsistent.

This diagnosis proves reproducible request/admission defects. It does not identify how much each defect influenced model choice, establish workout infeasibility, or guarantee the next solver/review/export stages will pass. No runtime implementation changes or paid calls were made during this root-cause investigation.
